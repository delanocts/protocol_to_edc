Operator guide · CDISC USDM v4.0.0

Protocol to USDM

Eight domain agents read an approved clinical protocol PDF and produce a CDISC USDM v4 study definition, a page-cited gap report, and a per-value provenance trail. It is an accelerator with a reviewer, not an autopilot.

One observed run — protocol I8R-JE-IGBJ, 73 pages, all 8 agents

313USDM objects, 27 entity types
91%quotes verified against the PDF
93%prompt-cache hit rate

01Setting up on a new machine

Python 3.11 or newer; developed and tested on 3.14.6. Nothing else needs installing — no database, no Docker, no Node toolchain.

Create a virtual environment and install

# from the project root
python -m venv .venv

# Windows
.venv\Scripts\python -m pip install -e ".[dev]"

# macOS / Linux
.venv/bin/python -m pip install -e ".[dev]"

Installing the project gives you the pte command as well as the libraries. If you would rather not install the package, three requirements files are provided and python run_build.py works without installation.

FileContents
requirements.txtruntime libraries, minimum versions
requirements-dev.txtthe above plus pytest
requirements-lock.txt48 packages pinned to versions known to work

Supply the API key

cp .env.example .env

Then set ANTHROPIC_API_KEY in it. That is the only secret the project has, it lives in one file at the project root, and it is gitignored. Every study on the machine shares it.

Confirm the install

.venv\Scripts\python -m pytest -q      # 99 passed, 1 skipped
.venv\Scripts\pte domains              # lists 8 agents, 2 levels

The test suite runs without an API key and without network access. If it passes, the schema, the terminology and all eight domain modules load correctly.

Two dependencies are imported nowhere and look droppable. cryptography is required because CDISC ships USDM-IG.pdf AES-encrypted and pypdf cannot open it without the library; python-multipart is required for FastAPI to accept the protocol upload in the web UI. Removing either breaks the tool in a way that only shows up at run time.

02Running a study

Two front doors onto the same engine. The terminal and the browser both call orchestrator.execute; neither reimplements the other. The only difference is that the web upload writes study.yaml for you.

Terminal CLI

# 1. scaffold the study folder
pte new I8R-MC-ABCD

# 2. copy the protocol PDF into
#    studies\I8R-MC-ABCD\input\protocol\

# 3. point study.yaml at the file
#    input:
#      protocol_pdf: "input/protocol/Prot.pdf"

# 4. verify — spends nothing
pte check I8R-MC-ABCD

# 5. run
pte build I8R-MC-ABCD

python run_build.py I8R-MC-ABCD is the same thing without installing the package.

Browser Web UI

python run_web.py
# http://127.0.0.1:8000
  1. Study — type an id, click Create
  2. Upload the PDF — this also rewrites study.yaml, so step 3 opposite does not exist here. It reports pages, characters and whether the text layer is usable.
  3. Configure — USDM version, output mode, effort, and the eight agent toggles
  4. Build USDM — live per-agent progress over SSE
  5. Results — gap report, document, validation, per-agent fragments

03How it works

One principle runs through the whole design, and most of the surprising decisions follow from it.

The model makes judgments. Code makes artifacts.

An agent decides what an epoch is, which arm a visit belongs to, whether a design is crossover or parallel. Python writes the JSON, mints the identifiers, derives the arm × epoch grid, resolves the terminology and validates the result. Nothing a model returns reaches the document without passing through a schema.

Four consequences worth knowing

No invented codes
An agent is shown the permitted values for a coded field and picks one by its wording. Python turns that choice into a Code object with the real C-code. A term matching nothing becomes a sponsor-defined value and lands in the gap report — it cannot become a plausible-looking but fictitious C99999.
Quotes are checked
Every extracted value carries the protocol text it came from and a page number. Each quote is then searched for in the PDF's own text layer. In the observed run 70 of 77 verified; the seven that did not are named in the gap report as reworded, page-shifted or too short to test.
Ids are placeholders until assembly
Agents emit @StudyEpoch:screening. The assembler mints StudyEpoch_1 and rewrites every reference to it. A reference to something no enabled agent produced cannot be written as a valid-looking id — it is reported as dangling.
Two entities have no agent
StudyCell (the arm × epoch grid) and StudyElement are joins over other agents' output, not readings of the protocol. They are derived in code. In the observed run that was 10 cells from 2 arms and 5 epochs.

The eight agents

Each is a manifest in config/domains/ plus a package under src/protocol_to_edc/domains/ holding its output schema, its prompt builder, its USDM mapping and its skill.md.

IG — Implementation Guide excerpts loaded into that agent's prompt. Codelists — codelists offered / total permitted terms across them. Skill — size of the hand-written domain knowledge file.

The entity names in a statement of work rarely match USDM v4. There is no StudyDesign class — there is InterventionalStudyDesign and ObservationalStudyDesign, with different required fields. There is no StudyObjective — objectives are Objective. Titles and identifiers hang off StudyVersion, not Study. Eligibility is split: the criterion text lives on the study version, the criterion's role on the design.

04End-to-end flow

Everything a run touches, in order. The teal path is the protocol itself: uploaded once, cached once, then read back by seven agents.

What one agent call contains

Reading the gap report

It is ordered by how much each item matters, not by agent, so a reviewer with twenty minutes should spend them at the top.

SectionWhat it holdsUrgency
1 — Structural errorsSchema violations, references pointing at nothingThe only items that make the output unusable
2 — Unverified quotesText the agent quoted that is not in the PDF as quotednot-found first — the value may not exist
3 — Low confidenceValues the agent flagged itself, below the thresholdUsually genuine protocol ambiguity
4 — Agent-reported gapsWhat the protocol does not settleNeeds someone who can consult the sponsor
5 — Missing required contentUSDM-required properties absent because an agent was offExpected when you disabled agents
6 — Sponsor-defined valuesNo published codelist matched the wordingSometimes correct, sometimes the wrong codelist

Output modes

Turning an agent off removes properties that USDM marks required, so an incomplete document is a normal state, not an error. The mode decides what happens next.

partial (default)
Emit what exists and report what is missing. What a statement of work usually means by "partial USDM output".
strict
Refuse to assemble. Use when the document has to be conformant and you would rather fail loudly than ship a gap.
stub
Insert minimal placeholders so the document validates, and list every one in the gap report. Use when a downstream consumer needs a loadable file today.

06Things worth knowing before you run it

Study ids must be plain ASCII. A hyphen copied from Word or a PDF is usually U+2011, a non-breaking hyphen that looks identical to a normal one and breaks Windows path handling. The tool rejects it at creation with the exact position, rather than letting it fail later: 

Study id 'I8R‑JE‑IGBJ' contains non-ASCII characters:
  position 3 '‑' (U+2011), position 6 '‑' (U+2011).
Use plain ASCII hyphens (U+002D), e.g. 'I8R-JE-IGBJ'.

Text-layer PDFs only. There is no OCR. A scanned protocol is refused at pte check with its character count, and the web upload says so before you waste a run on it.

Cost and caching

Two different caches, solving different problems. Understanding which is which explains most of what you will see in run_summary.json.

Prompt cache
Anthropic's, 1-hour TTL. Keeps the protocol resident server-side so agents after the first read it at a fraction of the input price. This is why one agent deliberately runs before the others — launched together, all seven miss the cache and each pays to write it. In testing that difference was a 0% hit rate against 93%.
Response cache
On disk, in .cache/, keyed by model, effort, prompt, schema and PDF digest. Saves the whole call on a re-run. Change one agent's prompt and re-run, and you do not re-pay for the other seven. --refresh <domain> drops one; --no-cache drops all.

Adding a ninth domain

Two files. Nothing else changes — the orchestrator, the assembler, the CLI and the web UI all read the registry, and none of them names a domain. 

config/domains/09_your_domain.yaml        # manifest
src/protocol_to_edc/domains/your_domain/
    domain.py   # PAYLOAD_MODEL, build_prompt(), to_usdm()
    skill.md    # how to read this domain in a protocol

The agent then appears in pte domains, as a toggle in the web UI, and in the dependency graph, without a line changing anywhere else.

Limits to be honest about

Schema complexity
The structured-outputs API rejects deeply nested schemas and several JSON-Schema keywords — minimum, maximum, pattern and others — at request time, after a run has started. tests/test_domain_schemas.py catches them for all eight agents beforehand. Keep constraints in pydantic validators, not in the schema.
CORE rules
Validation is JSON-schema plus referential integrity. CDISC's CORE conformance rules are not implemented; that would be a third layer in usdm/validator.py.
Visit timings
In the observed run only 3 of 8 visits received ISO 8601 timings. The agent declined to compute offsets it could not justify and logged gaps instead. That is the designed behaviour, and it is the first thing to tune if you want fuller schedules.
Scope
Stops at USDM. The Architect Loader Specification and the Rave load, edit checks, derivations and dynamics are out. The structure anticipates that phase — it consumes the USDM document rather than changing it.

If something goes wrong

SymptomCause and fix
ANTHROPIC_API_KEY is not set No .env at the project root, or the key line is blank. pte check reports it before any spend.
Protocol PDF not found input.protocol_pdf in study.yaml does not match the filename. The web upload sets this for you.
has no usable text layer Scanned PDF. Out of scope — run OCR elsewhere first.
Schema is too complex An agent's output model nests too deeply. Flatten it; size is not the limit, structure is.
did not parse as … The response was cut off at the token ceiling mid-value. Raise DEFAULT_MAX_TOKENS for that domain.
unresolved-placeholder Something referenced an entity no enabled agent produced. Usually correct — you disabled that agent.
cacheHitRatio near 0 A silent cache invalidator, or agents launched without the priming step. Check run_summary.json per agent.
